# ZDT 六轴机械臂 CAN 直连调试面板 — 使用说明

> `zdt_panel.py` — 六轴 ZDT 闭环步进电机的**安全**交互式调试面板（curses TUI）。
> 通过 USB-CAN 转接（SocketCAN）从 PC 直接控制机械臂 6 个电机。
>
> ⚠⚠ **本工具绕过 STM32 网关直接控制电机** — 固件限位开关保护不可用，
> 安全包络 = 本面板软限位 + 限速 + 看门狗 + 驱动器堵转保护 + **你的物理急停按钮**。
> 仅限 bring-up/调试，**禁止接入正常 VLA/LeRobot 推理路径**。⚠⚠

## 1. 环境与前置

| 项 | 要求 |
|----|------|
| 系统 | Ubuntu + 内核 CAN 模块（`peak_usb` 已加载即可，USBCAN-UCP100 免驱）|
| 接口 | `can0` @ **500 kbps**，先 `sudo ip link set can0 type can bitrate 500000 && sudo ip link set can0 up` |
| Python | conda 环境（如 `smolvla`），已装 `python-can` |
| 硬件 | 机械臂 6 电机已装配、**物理急停按钮可用**、手臂有支撑/稳定摆放 |
| 终端 | 需要真实 TTY（SSH 可用）；非 TTY 环境用 `--dump` |

**上机前安全检查清单：**
- [ ] 物理急停按钮已接好、可切断电机电源
- [ ] 手臂处于支撑/稳定位姿（**J2 肩抬、J3 肘为重力关节，失电会掉**）
- [ ] CAN 总线两端 120Ω 终端电阻正确
- [ ] 各驱动 OLED：`P_Serial=CAN1_MAP`、`CAN_Baud=500000`、`Response≠None`、**无 `Not Cal` 未校准提示**
- [ ] 6 个电机 **ID 互不重复**（曾遇到重复 ID 只扫出 5 台的坑）

## 2. 快速开始

```bash
# 1. 启动 CAN 接口（每次重启后）
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up

# 2. 先跑只读枚举（不运动，安全）
~/win_office/conda/envs/smolvla/bin/python Arm-robot_VLA/scripts/bringup/zdt_panel.py --dump

# 3. 进入交互面板
~/win_office/conda/envs/smolvla/bin/python Arm-robot_VLA/scripts/bringup/zdt_panel.py
```

命令行参数：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--iface` | `can0` | SocketCAN 接口 |
| `--addr-scheme` | `auto` | 寻址方案：`auto` 自动裁决 / `firmware`(1..6) / `pc`(2..7) |
| `--scan-max` | `8` | 扫描地址上限（电机 ID 可能 >8 时调大，如 16）|
| `--probe <id>` | 无 | dump 模式单地址探测（排查缺失电机）|
| `--watchdog` | `3.0` | 看门狗秒数（电机使能时生效）|
| `--dump` | 关 | 一次性文本枚举，不进入交互 |

## 3. 一次性枚举模式（--dump）

只读探测，**不发任何运动命令**，适合确认链路与寻址：

```bash
python zdt_panel.py --dump
# 输出示例
# == ZDT CAN 枚举 ==
# scheme: pc   在线电机: 6/6
#   J1  0x02  在线  FW/HW=0x5/0x82  flag=0x83
#   J2  0x03  在线  FW/HW=0x5/0x82  flag=0x83
#   ...
#   J6  0x07  在线  FW/HW=0x5/0x82  flag=0x83
```

**读懂输出：**
- **scheme**：`firmware`（J1=0x01..J6=0x06）或 `pc`（J1=0x02..J6=0x07）。`?` 表示无法自动裁决，需手动指定
- **flag 位**：`0x01`=使能中，`0x02`=已到位，`0x04`=堵转，`0x08`=堵转保护
- **少于 6 台** → 面板会列出**两侧各缺失的期望 ID** 并提示排查方向

排查缺台：
```bash
python zdt_panel.py --dump --scan-max 16      # 扩大范围，抓异常 ID
python zdt_panel.py --dump --probe 0x07       # 单地址探测
```

## 4. 交互式面板界面

```
ZDT 6-DOF CAN 直连调试面板   状态:ARMED      scheme:pc        ← 头部（状态/方案）
J# 名称             ID   FW/HW   使能 到位 堵转 电流mA MStep 减速比 备注   ← 表头
▶J1  shoulder_pan   0x02  0x5/0x82   Y   Y   -    123    16    50.00        ← 电机行（▶=选中）
  J2  shoulder_lift  0x03  0x5/0x82   Y   Y   -    456    16    50.89  ⚙    ← ⚙=重力关节
  ...                                                                      
选中 0x02  跟踪角 45.0°  步进 1.0°  限速 30RPM                          ← 详情行
参数: MStep=16 CAN_Baud=500k Response=Receive ...                        ← 参数行
>> 输入提示...                                                          ← 提示行（反色）
```

| 区域 | 含义 |
|------|------|
| 头部 | 当前**安全状态机**状态 + 寻址方案。状态见[安全模型](#7-安全模型) |
| 电机行 | 每台在线电机：关节槽、名称、ID、固件版本、状态位、电流、细分、减速比、备注（重力⚙/告警）|
| 详情行 | 选中电机的跟踪角（命令积分）、步进幅值、限速 |
| 参数行 | 读取 0x42 参数块后的 MStep/波特率/校验/响应模式等 |
| 提示行 | 需要输入确认（如 `CONFIRM`）时在此输入 |

## 5. 键位速查表

| 键 | 功能 | 安全等级 |
|----|------|----------|
| `e` / `F5` | 枚举总线（重扫）| 只读 |
| `↑↓` / `j` `k` | 移动选择 | 只读 |
| `1`-`6` | 跳到 J1-J6 | 只读 |
| `Enter` | 选中当前电机 | 只读 |
| `a` | **臂置**选中电机（使能保持；J2/J3 重力按 `y` 确认） | ⚠ 动作 |
| `d` | 失臂置（电机仍保持力矩） | 动作 |
| `E` | 全使能（所有电机保持力矩） | ⚠ 动作 |
| `D` | **全禁用**（⚠ 重力关节失力矩会掉，需支撑 + 输 `CONFIRM`） | ⚠ 高风险 |
| `x` | 停止选中电机 | 动作 |
| **`X`** | **广播急停** → 闩锁 STOPPED（**任意时刻含输入中/步进中**，全局最高优先级） | 🔴 急停 |
| `.` / `,` | 选中电机微步进 +/−（**非阻塞**，运动时可随时 `X` 急停） | ⚠ 动作 |
| `+` / `-` | 调步进幅值（0.1-5°）| 配置 |
| `s` | 设限速（RPM，硬上限 30）| 配置 |
| `t` | 单次遥测（flag/电流）| 只读 |
| `T` | 连续遥测开/关 | 只读 |
| `p` | 读电机参数块（0x42）| 只读 |
| `m` | 改参数（如 `18 2` = Response→Reached）| ⚠ 动作 |
| `i` | **改 CAN ID（不可逆！旧 ID 永久失效）**| 🔴 高风险 |
| `r` | 急停后复位闩锁（按 `y` 确认）| 恢复 |
| `?` | 帮助叠加层开/关 | 只读 |
| `q` | 退出（有使能电机时需输 `QUIT`）| 退出 |

## 6. 操作详解

### 6.1 枚举（`e`）
重扫总线并重新裁决寻址方案。**任何运动前必须枚举成功**。失败会显示原因（无响应/歧义/缺轴）。

### 6.2 臂置（`a`）与失臂置（`d`）
- **臂置 = 发送使能命令**（`F3 AB 01 00`）+ 进入 ARMED 状态 + **武装看门狗**
- 电机保持力矩 → 手臂不会掉
- **J2/J3 重力关节**臂置前面板直接显示 `[y/N]`，按 `y` 确认（防呆：确认你有支撑再动它）
- 失臂置只是退出 ARMED（不再允许运动命令），**电机仍保持力矩**，不会掉

### 6.3 微步进（`.` / `,`）
每次 ±1°（可调），**非阻塞**——命令发出后主循环继续轮询到位/堵转，期间界面实时显示 `STEPPING …flag=…`。发送前经**全部门禁**：
1. 必须处于 ARMED + 选中 + 在线
2. 目标角度 clamp 到该关节**软限位**（抵限位拒绝并提示）
3. 幅值不超过步进上限、速度不超过 30 RPM 硬上限
4. 发送 0xFD 脉冲命令 → 主循环每轮查 `0x3A`：到位/堵转/超时 → 更新跟踪角 → 回 ARMED

**运动进行中随时可按 `X` 急停**（主循环未被阻塞，急停全局优先）。

**堵转（flag 0x04）会立刻提示**——这是机械限位/卡死的第一道警报，听到/看到请立即检查并物理急停。

### 6.4 急停（`X`）

- 广播 `FE 98 00 6B` 到所有电机（立即停止运动）
- **全局最高优先级**：枚举/步进/输入 CONFIRM 中/确认框弹出中，按 `X` 都立即生效（不会被当输入字符）
- **不断电、不解除力矩** → 手臂保持位置不会掉
- 状态闩锁 **STOPPED**：所有运动命令被拒，直到按 `r` 弹 `[y/N]` 确认复位
- `Esc`：无确认框时 = 急停；在输入框内 = 取消输入

### 6.5 看门狗 + 自动遥测

- 电机使能后自动武装（默认 3 秒）
- **面板 ~1Hz 自动刷新所有在线电机状态**（flag + 选中电机电流），表格实时跳动；连续遥测 `T` 更密（~5Hz 选中电机）——这让看门狗在正常使用时保持活跃
- 超过阈值**无任何 CAN 通讯**（拔线/UI 卡死/总线死）→ 自动广播 e_stop + 闩锁 STOPPED
- 仅软件看门狗——进程崩溃时电机保持力矩（不运动），物理急停兜底

### 6.6 读参数（`p`）与改参数（`m`）
- `p`：读 0x42 参数块，详情行显示 **MStep / CAN_Baud / Checksum / Response / S_PosTDP / Ma_Limit / Vm_Limit / Clog_Pro**
- ⚠ **MStep≠16 会高亮告警** —— 3200 脉冲/圈假设失效，位置换算会偏，必须先校准
- `m`：改单个字段，格式 `m` 后输入 `<字段号> <值> [w]`（`w`=2 字节字段）：
  - `18 2` → Response 改为 Reached
  - `12 1800 w` → Ma_Limit 改为 1800mA
  - 字段号对照表见下文
- 写完建议 `p` 重读验证

**常用字段号（1-based）：** `7`=MStep，`12`=Ma_Limit(2B)，`13`=Vm_Limit(2B)，`16`=CAN_Baud，`17`=Checksum，`18`=Response，`19`=S_PosTDP，`20`=Clog_Pro

### 6.7 改 ID（`i`）——不可逆操作
- 格式：`i` 后输入 `<新ID> CONFIRM`
- **旧 ID 立即永久失效**，驱动器只能在 `0xAE` 换到的新地址应答
- 与在线电机 ID 冲突会被拒绝
- 改完自动提示重扫验证；**务必先在单台电机上演练**

### 6.8 退出（`q`）
- 无使能电机：直接退出
- 有使能电机：输入 `QUIT` 才退出 —— **不自动断电，保持力矩**（手臂不掉）
- 想关力矩：先 `D`（确认 J2/J3 有支撑）

## 7. 安全模型

**状态机：**
```
IDLE ──枚举──> ENUMERATED ──选择──> MOTOR_SELECTED ──臂置(确认)──> ARMED
ARMED ──步进──> STEPPING ──到位/堵转/超时──> ARMED
任意态 ──e_stop|看门狗|运动拒绝──> STOPPED (闩锁, 不自动离开)
STOPPED ──复位(确认)──> ENUMERATED
```

**安全铁律：**
1. **非 ARMED 不发任何运动命令**（代码层强制，UI 无法绕过）
2. 电机默认**保持力矩**（不断电）—— 重力关节不会掉
3. **e_stop 只停运动，不解除力矩**
4. 重力关节（J2/J3）臂置必须显式确认
5. 每关节**软限位** + **限速 ≤30RPM** + **步进 ≤5°** 硬上限
6. 看门狗：使能后 3s 无 IO → 自动 e_stop
7. 退出不自动断电；全禁用前必须确认支撑

> 面板只是软件包络。**物理急停按钮是最后防线** —— 异常时先按它。

## 8. 真机 bring-up 流程（推荐顺序）

1. **只读枚举** `--dump` → 6 台在线、scheme 正确、无 MISSING
2. 进 TUI，`e` 枚举 → 确认 J1-J6 映射
3. **非重力 J1** 臂置 → 微步 +1° → 确认方向与 `dir` 表一致 → 反向回原位
4. **逐关节**走 J2-J6，确认每轴方向与机械对应（底座/抬臂/肘/腕…）
5. `p` 读参数确认 `MStep=16`、`Response` 非 None
6. **急停演练**：`T` 连续遥测中按 `X` → STOPPED 闩锁 → `r` 复位
7. **看门狗演练**：臂置后拔 CAN 转接头 → ~3s 自动 e_stop
8. **逐轴标定减速比**（对比实测转角），把实测值固化进 `reduction_ratios`
9. 结束 `q`（保持力矩退出）

## 9. 常见问题排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 扫出 5 台（少于 6）| **电机 ID 重复**（只显示一个响应者）| OLED 核对每台 `ID_Addr`，改唯一后重扫 |
| 某地址无响应 | 编码器未校准（OLED `Not Cal`）| OLED 首次校准（正转一圈→反转一圈→高速）|
| 某地址无响应 | 该驱动 `Response=None` | OLED 改 `Response=Receive`；或 `--probe` 确认 |
| 某地址无响应 | 波特率/`P_Serial` 不一致 | OLED 核对 `CAN_Baud=500000`、`P_Serial=CAN1_MAP` |
| 某地址无响应 | CAN 接线/端子/终端电阻 | 检查该节点线缆、120Ω 终端 |
| 全部无响应 | 总线没电 / 接口没 up / 转接头没插 | 检查供电、`ip link show can0` |
| scheme=? | 缺轴/部分匹配，两侧都不完整 | `--addr-scheme firmware|pc` 手动指定或先修缺轴 |
| MStep≠16 告警 | 细分不是 16 | 3200 脉冲/圈假设失效，先校准再运动 |
| 微步进被拒 | 抵软限位 / 未臂置 / 超幅值 | 看提示：反向步进 / 先 `a` 臂置 / 调小步进 |
| 步进后报"堵转!" | 机械限位/卡死/负载过重 | **立即物理急停**，检查机构 |
| 看门狗触发 | 拔了线 / UI 卡死 / 总线死 | 复位接线，`r` 复位后重枚举 |
