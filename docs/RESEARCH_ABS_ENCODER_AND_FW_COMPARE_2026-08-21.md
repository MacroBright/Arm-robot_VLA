## 一、核心问题：机械臂能否绝对磁编码器位置读取（断电记忆）

### 1.1 结论

**能——但当前系统（本项目 + 开源固件）都没用上。**

驱动器（张大头 Emm_V5/ZDT 闭环驱动器）**内置绝对磁编码器**，通过特定命令可读取"断电后转动、上电仍能识别"的真实角度。但本项目 PC 驱动和开源 STM32 固件**全链路只用 0x36（增量计数）**，完全未使用绝对编码器命令。

### 1.2 编码器命令体系（说明书 V2 Rev1.0 证据）

| 命令 | 名称 | 一圈范围 | 断电记忆 | 性质 | 本项目是否用 |
|------|------|:--------:|:---:|------|:---:|
| **0x29** | 编码器原始值 | **0-16383**（磁编码器固有） | **✅ 绝对** | 磁铁角度→绝对刻度 | ❌ |
| **0x31** | 线性化校准后编码器值 | 0-65535（×4 倍频） | **✅ 绝对** | 绝对刻度（更高精度） | ❌ |
| **0x30** | 实时脉冲数 | 多圈累加 | ❌ 增量 | 增量脉冲计数 | ❌ |
| **0x36** | 电机实时位置角度 | ×10 度（一圈 3600） | ❌ 增量 | 位置计数（可 0x0A 6D 清零） | ✅ 唯一使用 |

**关键原理**（说明书 §7.4.4）：
- **0x29** 读的是磁铁相对转子磁场的**角度刻度**（0-16383 = 一圈），靠磁场位置感知，**不依赖脉冲累计**。转子物理位置不变 → 读数不变。
- **断电 → 转动电机 → 上电 → 0x29 仍能读到新的真实角度** ✔

### 1.3 为什么现在"上电 pos=0"

因为本项目（`zdt_driver.py`/`zdt_anchor.py`）**全部用 0x36**：
- 0x36 是驱动器 RAM 里的**增量计数**，上电清零、可被 `0x0A 6D` 清零
- 所以每次上电 0x36 自动 = 0 → `anchor` 算出 0 或初始位
- 不是绝对编码器本身做不到，是**没用对命令**

### 1.4 落地前提：本机固件是否支持 0x29？

这是关键分叉，需真机验证（**请运行 `raw 29`**）：
- **有返回**（如 `29 26 72 6b`）→ 支持绝对编码器，**可实现断电记忆定位**（把 `0x29` 接入 `zdt_driver`）
- **超时** → 本机固件不支持（如同 0x22/0x9A），只能靠 PC anchor 方案

### 1.5 开源固件的佐证

开源 STM32 固件里定义了 `S_ENCL = 0x31`（Emm_V5.h:71）**但应用代码零调用**——连开源方案都没用绝对编码器。它只调 `S_CPOS`(0x36)。

## 二、开源固件（zero-robotic-arm STM32）的姿态/限位/回零逻辑

### 2.1 上电姿态确认：硬编码，不读编码器

- `robot_init()` 用 `memcpy(g_robot.joints, g_joints_init, ...)`（robot.c:745）**直接硬编码出厂初始位**
- 上电 `current_angle` = 出厂标准姿态角 `[90,90,-90,0,90,0]`（g_joints_init.current_angle）
- **断电后外力转动再上电 → 固件毫不知情**，默认仍是出厂角
- 唯一的姿态修正发生在 `soft_reset`/PID 闭环时读 0x36

### 2.2 限位机制：两套并存

**① 物理限位开关（GPIO 硬件）—— 真正的运动停机保护**
- 每关节一个 GPIO 限位开关，上下升沿触发外部中断（robot.c:208）
- 中断 → `robot_joint_limit_happend`（robot.c:164）→ **立即停该电机**（`Emm_V5_Stop_Now`）→ 压事件
- 这是"撞限位停车"的唯一真正保护

**② 软件角度软限位（min_angle/max_angle）—— 只在校验环节生效**
- `robot_angle_map`（robot.c:264）只在 `soft_reset` 换算时对当前角做合法性校验/吸附
- **不拦截正常运动的目标角**：`robot_joint_rotate_to` 绝不做 min/max 钳制
- 结论：**固件本身没有"目标越界钳制"**，VLA 若安全需要，须上位机自己做

### 2.3 回零 / 初始位：两种复位

**① 硬件复位 `hard_reset`（robot.c:246-262）= 电机回机械限位零点**
- 逐个关节向 `reset_dir` 运动 → 撞限位开关 → `Emm_V5_Reset_CurPos_To_Zero`（0x0A 6D）把驱动器当前位置清零
- **把"限位开关点"定义为电机零点**（相对约定，非多圈绝对）
- 完成后 `current_angle` 覆盖回出厂角

**② 软件复位 `soft_reset`（robot.c:300-336）= 发命令回 g_joints_init 角度**
- 读 0x36 修正当前角 → `robot_angle_map` 校验 → `robot_joint_rotate_to(absolute=true)` **绝对运动到出厂角**
- 依赖"上电 current_angle = 出厂角"这一假设，**无法纠正断电后外力造成的真实偏差**（除非先 hard_reset）

### 2.4 姿态跟踪：双源

- **命令设值**（rotate_to 直接写 current_angle / 累加）——单发点动路径
- **编码器覆盖**（PID 闭环每周期读 0x36）——auto/remote 连续轨迹路径
- 驱动电机永远用**相对运动**（`Emm_V5_Pos_Control` raF 恒 false）

### 2.5 绝对编码器：完全没用

- 应用代码唯一读编码器 = `S_CPOS`(0x36)，0x36 是相对实时位置
- `S_ENCL`(0x31) 只定义无调用；无任何 0x29；`Emm_V5_Origin_*` 回零 API 零调用

## 三、本项目（Arm-robot_VLA）的运行/调试逻辑

### 3.1 架构

PC 直连 CAN 到 6 个 Emm_V5 驱动器（ADR-005，绕过 STM32）。核心模块 `lerobot_robot_massage/zdt/`：
- `zdt_driver.py`：CAN 帧收发、单条命令（读 0x36/0x27、0xFD 运动、0xF3 使能等）
- `controller.py`：`ZdtController` 高层控制（set_joints/rel_rotate/soft_reset/set_joints_safe/check_limits_real）
- `safety.py`：`SafetyMachine` 状态机 + 限位 clamp + 漂移守卫
- `config.py`：常量 + CALIB(k,b)/CALIB_OFFSETS 标定表
- 交互工具 `scripts/bringup/zdt_interactive.py`：调试 CLI（anchor/cal/safe mv/fdrel 等）
- 上电锚定 `scripts/bringup/zdt_anchor.py`：读 6 轴真实角度

### 3.2 姿态确认：PC 上电 anchor（方案 A，本次选定）

- 上电后 0x36 全为 0（增量清零）→ `zdt_anchor.py` 读 0x36 + CALIB(k,b) 换算出真实角度
- **依赖人为先把机械臂摆到初始位**（因为 0x36 不记忆）
- 读出的"真实角度"实时反映当前位，作为限位判断（check_limits_real）的基准

### 3.3 限位：上位机软件限位（与固件相反）

- `config.py` `FIRMWARE_JOINT_LIMITS`：真机 anchor 实测值 J2/J3=(0,120)、J5=(0,180)
- `controller.set_joints_safe`：读 0x36 真实位置 → clamp 到限位 → 运动
- `controller.check_limits_real`：实时守卫，J2/J3/J5（high_freq）目标越界 → 单轴 stop + 告警
- 交互工具 `safe mv`：验证用
- **本项目没有物理限位开关依赖**（PC 直连，绕过了 STM32 的 GPIO 限位），全靠上位机软件限位

### 3.4 回零/初始位：soft_reset → 出厂角

- `controller.soft_reset()`：发 0xFD 相对运动回 `JOINT_INIT_ANGLE_DEG`（固件出厂角 [90,90,-90,0,90,0]）
- 用 `_tracked_angles`（命令积分）算相对增量
- **同样是"回到出厂位"的约定，不依赖编码器绝对零点**

## 四、两者底层逻辑对照（核心差异）

| 维度 | 开源固件（STM32） | 本项目（PC 直连 CAN） |
|------|------|------|
| **位置来源** | 命令设值 + 0x36 编码器 PID 闭环 | 0x36 ×CALIB(k,b) 换算出真实角度 |
| **上电姿态** | 硬编码出厂角 [90,90,-90,0,90,0]，无姿态恢复 | 0x36 清零，需人为摆初始位后 anchor |
| **绝对编码器** | 完全不用（0x29/0x31 零调用） | 完全不用（只用 0x36） |
| **运动停机保护** | **GPIO 物理限位开关**（中断停机） | **上位机软件限位**（clamp + check_limits_real） |
| **软限位拦截** | 不拦截正常运动目标角（只 soft_reset 校验） | 拦截运动目标（set_joints_safe clamp + 实时守卫） |
| **回零点定义** | hard_reset = 回限位开关点 → 0x0A 6D 清零 | soft_reset = 回出厂角 g_joints_init |
| **姿态跟踪** | rotate_to 设值 / PID 闭环读 0x36 | tracked_deg 命令积分 / 0x36 真实角度（限位用） |
| **断电记忆** | 无（固件不知断电后转动） | 无（0x36 清零，需 anchor） |

### 关键共性

**两者都不使用绝对磁编码器（0x29），都不具备"断电后自动识别姿势"能力。** 这是当前架构共同的根本限制——不是硬件做不到，是软件都没用对命令。

## 五、可行性建议

### 若本机固件支持 0x29（待真机 `raw 29` 确认）
1. 在 `zdt_driver.py` 新增 `read_abs_enc(addr)`（读 0x29）
2. 上电后优先读 0x29 绝对刻度 → 结合装配标定（每关节的绝对刻度↔角度关系）直接得到真实角度
3. **实现真正的断电记忆定位**（断电转动再上电也能识别），彻底摆脱"人为摆初始位"

### 若本机固件不支持 0x29
- 维持 PC anchor 方案（`zdt_anchor.py`），每次上电快速锚定
- 可考虑向卖家确认固件升级支持 0x29 的可能性

### 安全提示（对照固件得出的洞察）
- 开源固件靠**物理限位开关**兜底；本项目靠**上位机软件限位**（check_limits_real 只覆盖 J2/J3/J5）
- 若本项目完全无物理限位，J1/J4/J6（360° 旋转关节，软件限位跳过高频检查）的安全性需重新评估
